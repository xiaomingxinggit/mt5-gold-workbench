# 行情日志

行情日志是工作台内的本地短帖页面，用于保存黄金行情判断、截图和持仓复盘。它不向外部平台发布内容，也不会向 MT5 发送交易请求。

## 使用方式

1. 连接 `USC` 美分账户，在侧栏打开“行情日志”。每篇帖子和每条关联持仓都记录发帖时的 MT5 登录号与服务器，并按这两个字段隔离。
2. 点击“写一条日志”，输入正文，可选最多 4 张本地图片、最多 20 笔当前 `XAUUSDc` 持仓。正文最多 2100 字；每张图片最多 8 MiB，支持 PNG、JPEG、WebP、GIF。
3. 点击“发布到本地”。保存前会重新核对账户和选中的持仓；若持仓已变化，草稿仍留在编辑弹窗中，供修改后重试。
4. 帖子按发布时间倒序显示，每页 10 条，可用“上一页 / 下一页”翻页。记录轨迹标题栏可选择年份查看该账户当年的发帖热力图；年份切换不筛选下方的最新帖子。删除帖子前会二次确认，同时移除该帖的本地图片副本。

帖子绑定持仓时会保存**发帖当时**的账户、持仓标识、Ticket、方向、手数、开仓价和浮动损益。帖子中“发布时浮动”是历史快照，不代表当前浮动损益。单帖可关联多笔持仓；同一持仓也可关联多篇帖子。发布前再次核对每笔持仓是否仍属于当前账户；不能把另一账户的持仓关联进来。

工作台读取的是当前 MT5 终端连接的账户，不会在后台替用户切换登录。MT5 Python 的 [`login()`](https://www.mql5.com/en/docs/python_metatrader5/mt5login_py) 可切换连接账户；切换后工作台会重新确认账户，并只展示该账户的帖子与关联持仓。过去账户的数据仍保存在本地，重新连接该账户即可查看和同步。若未来要同时操作多个账户，需要单独设计终端实例与账户路由，本功能不会把当前终端的交易或成交归给另一个账户。

## 平仓结果

打开行情日志、手动刷新，或页面保持打开时约每 30 秒，会读取 MT5 当前持仓，并在后台核对已结束的关联持仓。关联使用稳定的 `POSITION_IDENTIFIER`；MT5 历史成交可通过 `history_deals_get(position=...)` 按 `DEAL_POSITION_ID` 查询。[持仓标识说明](https://www.mql5.com/en/docs/constants/tradingconstants/positionproperties)、[Python 历史成交接口](https://www.mql5.com/en/docs/python_metatrader5/mt5historydealsget_py)。

只有当前持仓列表成功读取，且历史成交能确认该持仓阶段已结束时，帖子才显示“已平仓”。部分平仓仍显示“持仓中”；MT5 断线、历史查询失败、票号发生无法解释的变化或账户切换时显示“结果待核实”，不把未知结果显示为零。净额账户发生反向开仓时，MT5 可能保留原 `POSITION_IDENTIFIER`；程序按发帖时间截断到首次反向成交，不把后续新方向盈亏算入原帖。如果帖子发布在一次反向成交之后，而该成交的费用无法可靠分摊到新旧持仓阶段，则保留“结果待核实”。

已核实的最终结果汇总该持仓阶段成交的 `profit + swap + commission + fee`，以账户币种 **USC** 保存。界面同时显示按 **100 USC = 1 USD** 换算的 USD 金额。它是成交记录的净资金结果，不包含尚未结算的实时浮盈亏。

## 活跃看板与本地数据

“记录轨迹”借鉴贡献日历：选择当前年或该账户曾发帖的年份，查看该日历年的发帖热力图。每个方块代表一个本地日，颜色表示当天发布的**帖子数**，不是成交次数或收益；闰年包含 2 月 29 日，当前年份显示至今天。悬停可查看日期和数量；上方的累计帖子、过去 30 天帖子数和过去 365 天活跃天数保持原统计范围，不随年份切换。[GitHub 贡献日历参考](https://docs.github.com/en/account-and-profile/concepts/contributions-on-your-profile)。

数据库和图片都位于程序旁的 `state/journal/`：

```text
state/journal/
├── journal.sqlite3
└── images/
```

备份时应同时复制数据库和 `images/`。断开 MT5 后，本次运行仍可浏览已识别账户的本地帖子；重新启动后需先连接该账户以确定日志范围。图片会复制到本地目录，删除原始选图文件不会影响已发布帖子。
